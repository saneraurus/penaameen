# PENA AMEEN Data Entity Catalog

**Phase:** 4 — Data Architecture

**Status:** PROPOSED logical entity catalog. Fields are semantic requirements, not physical columns, SQL types, ORM properties, or migrations. `Required` means required for the entity’s approved logical purpose; final field-level enforcement depends on client policy, Phase 4 source data, and later implementation design.

**Logical entity count:** **81** (including association, audit, and system entities).

## 1. Catalog conventions

- **Immutable** fields preserve identity, historical evidence, or append-only audit facts; corrections create a controlled new record/version or audited transition rather than silently rewriting history.
- **Mutable** fields may change through authorized workflows and audit rules; their exact permissions are not assumed.
- **Derived** fields are calculated/read-model values and must not become a competing source of truth.
- **Source/migration** fields retain source identifiers/provenance only when available; `UNKNOWN` source data remains unknown.
- **Deletion/retention** entries are architectural handling guidance, not a legal retention policy. Client/legal decisions remain required.
