# PENA AMEEN Accessibility Constitution

**Phase:** 6 — Implementation Constitution

**Status:** Mandatory accessibility implementation rules. This does not claim formal certification; final conformance target, test tooling, and supported assistive-technology matrix remain approval work.

## Mandatory requirements

- Use semantic landmarks, headings, lists, forms, tables, buttons, links, dialogs, status regions, and media alternatives according to meaning.
- Every interactive control is keyboard operable with visible focus and logical focus order.
- Every form field has persistent programmatic label, required/optional indication, help/error association, and safe validation announcement.
- Dialogs/menus/autocomplete/media galleries manage focus, escape/close behavior, keyboard navigation, and return focus correctly.
- Tables have captions/context, headers, sortable/filter state, accessible responsive fallback/overflow behavior.
- Images have approved meaningful alt/caption/context or explicit decorative treatment; text required for task/claim is not image-only.
- Color, icon, motion, hover, position, or placeholder cannot be the only carrier of state, error, required field, price, stock, payment, shipping, or authorization information.
- Respect reduced-motion preference; no motion is necessary to understand/completion.
- Preserve readable text, zoom/reflow, touch targets, and compact/expanded task flows.
- Test public Shop/Product/Checkout/Tracking, account, admin form/table/dialog, loading/error/empty/processing states with actual implementation.

## Review rules

Accessibility review is required for new component, route, form, modal/dialog, table, media pattern, responsive behavior, state feedback, and CSS/token change. A passing visual screenshot is not accessibility evidence.
