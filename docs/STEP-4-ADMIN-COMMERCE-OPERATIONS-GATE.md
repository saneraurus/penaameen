# Step 4 Admin Commerce Operations Gate

**Status:** Read surfaces implemented locally; privileged provider actions remain blocked until sandbox/SOP acceptance.

## Implemented modules

- `/admin/customers` and `GET /api/admin/customers`
- `/admin/payments` and `GET /api/admin/payments`
- `/admin/fulfillment` and `GET /api/admin/fulfillment`

All routes use server-side capability checks and no-store responses. Customer data is minimized to operational context. Payment and fulfillment values are projections of the authoritative `Order` record.

## Explicitly blocked actions

- Manual payment verification without verified evidence.
- Refunds without provider sandbox and finance SOP.
- Shipment creation without provider sandbox, package rules, origin, and SOP.
- Label printing without provider support.

No fake tracking number, payment status, shipment status, or provider response is generated by these modules.

## Local acceptance

```text
npm run check
npm run test:e2e
```

Authenticated Admin E2E requires a staging Clerk staff account and seeded operational records. It must be added after staging credentials are available.
