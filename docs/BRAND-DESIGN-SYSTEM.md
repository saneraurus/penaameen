# PENA AMEEN Brand Design System

**Phase:** 5 — Design System & UX Blueprint

**Status:** Brand-application governance with explicit uncertainty. No final logo rule, color, font, imagery direction, illustration system, icon set, or cultural claim is approved by this document.

## 2. Brand expression principles

Until brand assets are approved, the interface should express PENA AMEEN through **semantic behavior**, not invented aesthetics:

- clear educational and commerce hierarchy;
- calm, readable, non-manipulative information presentation;
- accurate product, price, availability, order, and shipment feedback;
- respectful treatment of AL-BARQY, ACM, community, and learning content;
- accessible contrast and readable typography roles;
- restrained use of visual emphasis for primary tasks and critical states;
- source-backed testimonials, method claims, and media only.

These are UX principles, not a claim of formal brand personality.

## 4. Color governance

No final hexadecimal values are defined. The token system uses semantic roles such as `brand`, `surface`, `text`, `success`, `warning`, and `error`. Approved brand values must be mapped only after accessibility contrast validation and client approval.

Brand color must not be used as the sole carrier of availability, payment, shipping, error, success, or required-field meaning.

## 5. Typography governance

No font is approved. Typography is defined by semantic roles, readable scale relationships, line-height, and responsive behavior. Final font selection must validate licensing, Indonesian/Latin character coverage, performance, legibility, and accessibility. See `docs/TYPOGRAPHY-SYSTEM.md`.

## 6. Imagery, illustration, and iconography governance

| Area | Interim design rule | Approval gate |
|---|---|---|
| Product imagery | Use actual approved product media; do not use decorative substitute product imagery as factual representation | Media rights/source/export and brand approval |
| Article/education imagery | Use approved editorial assets only; captions/alt/source matter | Content/media/legal review |
| Branch/event/gallery | Show only approved, rights-cleared context; avoid implying local service/product availability | Branch/event/media approval |
| Illustration | No style direction assumed; use functional neutral placeholders only if approved | Brand direction required |
| Iconography | Use accessible semantic icon role; pair critical meaning with text/label | Icon family/style approval required |

## 7. Tone and content hierarchy

Tone must be clear, respectful, factual, and task-oriented. It must not promise learning outcomes, delivery times, stock, payment completion, branch services, testimonials, or policy terms not backed by source/approval. Customer-facing errors focus on next actions; staff-facing errors preserve diagnostic context without exposing secrets/PII.

## 8. Brand approval workflow

Before final visual implementation, PENA AMEEN should provide:

1. logo asset package and usage rules;
2. brand guide, colors, typography, and approved fallback policy;
3. imagery/illustration/iconography guidance;
4. approved language, tone, cultural positioning, claims, and testimonials;
5. approved source media/rightsholder evidence;
6. named brand/design approval owner and review workflow.

Until then, this document supports semantic design governance only.
